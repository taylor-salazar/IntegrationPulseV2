# Manual BAS/SAP validation checklist

**Not executed by this audit.** Run after pulling the audit branch into BAS. Prefer DEV/test integrations and synthetic payloads; do not use an employee production data flow for mutation tests. Passing automated tests does not authorize release with the defects in [defects.md](defects.md).

Record branch/commit, browser/UI5 versions, destination names and tenant/space, integration runtime ID/name/version/package, expected design-time ID/version, UTC timestamps and sanitized response details. Do not attach tokens, cookies, secrets or actual HR payloads to GitHub. For known failed local assertions, validate the UI/external impact; do not repeat pure serialization unit tests manually.

## Responsive and accessibility pass

For **each** approximate viewport below, open Home, catalog category/cards/list, Detail with long parameter values and timer, Monitoring, many-log Detail, payload and immediate-run dialogs. Read-only; cancel dialogs. Preconditions: long integration/system names and a large test list are available. Expected: usable scrolling, no unreachable actions, sensible wrapping/popins, readable controls and stable focus. Failure: horizontal clipping, overlapping labels, off-screen footer buttons, tiny unusable tables, scroll traps or content hidden by fixed dimensions.

| Viewport | Extra focus |
|---|---|
| 390 × 844 (mobile-style) | Home fixed columns; sidebar; timer fields; modal buttons; horizontal versus vertical scrolling |
| 768 × 1024 (tablet) | Two-column parameter minimum widths, table popins, long category names |
| 1366 × 768 (laptop) | Dialog height, bottom controls at normal/125% zoom, dense parameter and monitoring tables |
| 1920 × 1080 (desktop) | Multi-column alignment, long field labels/values, list responsiveness |
| 2560 × 1440 (large desktop) | Maximum content width, excess spacing, dialog placement and readability |

Keyboard check: Tab/Shift-Tab through navigation, tiles, category actions, forms and dialogs; use Enter/Space for actions; Escape to cancel where supported; verify focus returns to invoker. Check screen-reader/Accessibility panel names for parameter Inputs, checkboxes and icon-only actions; label association, status announcements and busy state. Do not equate XML Label presence with a verified accessible name.

## DevTools performance pass

Preconditions: stable DEV dataset; Network “Preserve log”; Console open. Read-only steps:

1. Record a cold and warm load of Home/catalog/Monitoring. Count repeated runtime collections, metadata GETs and per-integration logs/payloads; note failed-request cascades. Compare with local operation counts in [performance review](performance-ui.md).
2. Record Performance while moving between category/list/detail and scrolling the largest available list. Observe long main-thread tasks, layout/recalculate-style work and delayed input response; record traces and dataset size without inventing an SLA.
3. Navigate the same sequence repeatedly, close dialogs and return to the starting page. Compare active requests/listeners and optional heap snapshots after GC. Look for monotonically retained controllers/models/EDMX/dialogs; normal temporary growth is not itself proof of a leak.
4. Inspect slow responses separately from client rendering, status/size and duplicate requests. Save sanitized waterfall/console findings. No strict latency target is defined in the repository.

Release exit: owner reviews each reproduced defect/fix, executes applicable external checks, records outstanding exceptions and explicitly accepts remaining risk. This checklist does not declare release approval automatically.
